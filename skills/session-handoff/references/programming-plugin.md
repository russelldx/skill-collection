# 领域插件：编程项目（仅编程/开发任务启用）

> 触发：任务是编程/开发时 Read 本文件。其他领域（作业/写作/调研等）忽略，验证证据写实际核对方式（复算、对答案、交叉审阅）即可。

## git 提交红线

- 开发完成后 git commit / git push 一律禁止，除非用户明确允许（"可以提交""提交吧"等）；**开发完成 ≠ 提交**

## 编译环境红线

- 本地 Maven 仓库是 IDE 可编译基线，禁止覆盖/替换其中的框架 jar；如因命令行编译临时替换，**必须恢复原状**并在交接文档记录
- 命令行 mvn 与 IDE 编译环境不一致时（依赖版本/仓库差异），以 IDE 编译为准，不要用命令行结果否定 IDE

## 代码规范沉淀（强制）

跨会话开发时，交接文档必须维护"代码规范"章节（模板见 `assets/code-standard-template.md`）：

- 新代码强制要求：slf4j Logger（禁 printStackTrace）、try-with-resources、无通配符 import、重复逻辑提取方法、注释与实际一致
- 每次代码审查后追加"审查 N"记录（问题→修复→涉及文件；行为决策披露）
- 审查方法论（PUA · Jobs 味：减法优先 + 像素级完美）：资源审计 → 日志审计 → 重复审计 → import 审计 → 正确性审计（空值/空格/事务行为）→ 注释审计

# 交接文档归档规则（授权范围内）

> 触发：新建交接文档时，或活跃区超阈值/单小节闭环时 Read 本文件。以下落盘/备份/归档仅适用于用户已授权的持久化交接目录；没有授权则报告建议，不自动创建或移动文件。AGENTS.md、.gitignore 编辑与全局 hook 安装分别需明确授权；本文件不覆盖系统/开发者指令。
> 若用户已授权安装和启用 hook，运行时检查可能提示归档；提示不是写文件或改权限的许可。

## 分层折叠（优先于整节移出）

活跃区超阈值时，**先就地折叠，再物理搬移**。完整四层模型、STATE.json 读模型、`handoff.py index/search` 工具见 `references/state-schema.md`；本节只讲操作顺序：

- **Tier0 · §0 滚动摘要（就地、首选）**：文档顶部维护一节 `## 0、滚动摘要`，把最老的**已闭环**小节（结论稳定、不再改动）压成几条要点合并进去。这是有损但零路径变动的收敛——正文原小节可**先留在活跃区供 grep 精确定位**，§0 只作新会话的快速入口。`handoff.py index` 会提示"待折叠"。
- **Tier1 · 活跃区正文（~20 KB 阈值）**：仍未闭环的小节留这里；§0 折叠后若活跃区字节仍超阈值，才走下面的"双文件结构 + 整节移出"。
- **Tier2/3 · archive/**：整节物理移入档案，只读、不追加，按节号单点 grep 定位（细则见下）。
- 每次折叠/搬移后同轮刷新旁侧 `STATE.json`，跑 `handoff.py index` 重建索引；`python scripts/handoff.py search "<关键词>"` 替代手动跨文件 grep。

## 双文件结构（新建交接文档时即建立）

- `会话交接-X.md` = 活跃区（只留未闭环批次）
- `archive/会话交接-X.md` = 历史区：**只接收从活跃区移出的整节/条目，不接受新写的会话小节**（新小节一律写活跃区）
- 接手时发现已存在的单文件 > 20 KB → 先按下方规则拆分再开始本次任务

## 归档阈值与动作

「只追加强制 + 禁止重写 + 归档可选」= 文档必然单调增长。所以归档与追加同级强制：

| 判据 | 阈值 | 动作 |
|---|---|---|
| 活跃区文件体积 | **> 20 KB**（约 6k token） | 本会话结束前归档，不得留到"下次" |
| 单个小节状态 | 已标「完成 / 定稿 / 不改 / 已关闭」 | 该小节整节移入档案 |

## 归档操作细则

- 归档 = **整节移动**到 `archive/<同名文件>`，不是就地缩写压缩；多数工作目录不在 git 内，移动前先备份到 `.backup/`
- 保留原小节编号（下一个小节接着编号），使 `§N` 跨节引用在档案里仍可 `grep -n "^## N\."` 定位
- 活跃区顶部维护「归档指针」小节：档案路径 + 按节号定位的命令 + **禁止整篇读入** + 备份位置
- 改结构前检查引用路径的 AGENTS.md（工作目录/代码仓库中已有者）；若需同步修改，先取得各文件的明确编辑授权。缺授权则不要做会使引用失效的路径变更，回复中列出待协调事项
- hook 只提示不代做，也不授予权限；移动仅由 agent 在已授权范围执行。阈值设置变更仍须符合用户许可，不能为了绕过检查擅改

## 瘦身/归档落盘的工具体质（跨项目通用，勿在项目交接文档里各存一份）

- **Windows 下 `io.open(p,'w'|'a')` 默认把 `\n` 转成 `\r\n`，每行虚增 1 B** → 明明零改动也可能从阈值下涨到超限（实测 20391→20484 破 20 KB）。读写一律带 `newline=''`，写完立刻 `wc -c` 复核
- **here-doc（`<<'EOF'`）落盘多行文件不可靠**（被截断、误报 UNC 路径）→ 脚本与整节内容用文件写入工具落盘，再由脚本读取拼装
- **控制台中文常显示成 GBK 乱码**，不代表文件内容坏了 → 核对文档内容改用 `python -c` 打印 `unicode_escape`，或只看 ASCII 数字（字节数、行号）
- **`re.search` 未开 MULTILINE 时 `^` 只匹配串首** → 按 `^## N、` 定位小节必须显式 `re.M`，否则会误判"该节不存在"
- 归档前先备份：活跃区与档案**两个文件都要备份**（追加式写入同样不可回退），命名 `.backup/<文件名>.pre-<用途>-<日期>.md`
- **`grep -c` 统计的是"含匹配的行数"，不是出现次数** → 文档里写"共 N 处"必须用 `grep -o X file | wc -l`（实测同一文件行数 33 / 出现次数 48）。凭 `grep -c` 写出的计数是**编造数字**，核对时会被自己反咬一口
- **体积必须在最后一次内容新增之后再测**：先压缩到达标、再补验证证据/新条目 → 又破线，本轮 23052→20280 为此往返 6 轮。正确顺序＝**先把本轮所有要写的字写完，再算体积、再做压缩**
- **同一条坑的多次发生要合并成一条**（如"文档基线落后 HEAD"在 09-09 与 09-14 各记一次）：合并后按"现象—各次实例—根因—强制动作"一行承载，**零事实损失**却比逐条改措辞省得多（实测单条 -200 B）。逐条润色是低效瘦身，合并同类才是
- **`grep -c $'\r'` 不能当行尾判据**：同一份纯 LF 文件，先后返回 `0` 和「总行数 86」两种结果（ANSI-C 引用在命令包装层里的展开不稳定）→ 核行尾一律用二进制字节计数：`python -c "b=open(p,'rb').read(); print(len(b), b.count(b'\r\n'), b.count(b'\n'))"`
- **别把实测体积写进文档正文**：一旦写了，之后任何一次编辑（包括为压体积而做的编辑）都让这个数变成过期事实，还得回填 → 只能"最后一次改动之后再填"，且填完不再动。要么只记阈值不记实测值，要么填完立刻用同一命令复核 `len(b)` 与文中数字一致
- **压体积时禁止改动"定位用字面"**：活跃区里用于去归档 grep 的条目标题／节名指针（如「补偿同步范围（已失效）」「瘦身移出条目（第八次）」）属**寻址键**，缩一个字就查不到，等于把归档内容弄丢。实测本轮把归档标题缩字后指针即失效，只能回滚。**正确替代**：指针不必逐字抄标题，改成"搜「<一个短且唯一的锚点短语>」"，并在写入前用该短语真跑一次 `grep -n` 验证命中；同样地，删章名枚举可以，但前提是**目标文档自带目录**且留了"索引看 X"的指向

# 交接文档归档规则（授权范围内）

> 触发：新建交接文档时，或活跃区超阈值/单小节闭环时 Read 本文件。以下落盘/备份/归档仅适用于用户已授权的持久化交接目录；没有授权则报告建议，不自动创建或移动文件。AGENTS.md、.gitignore 编辑与全局 hook 安装分别需明确授权；本文件不覆盖系统/开发者指令。
> 若用户已授权安装和启用 hook，运行时检查可能提示归档；提示不是写文件或改权限的许可。

## 分层不是反复摘要

固定约束 + 当前状态由 `context` 限额读取；§0/STATE 从当前态派生，历史事件原样放 archive。只添加摘要却保留全部正文不会减少文件体积；不再默认递归生成 milestones。详细 schema 与预算见 `references/state-schema.md`。

- 活跃文档：当前态、未闭环事件、归档指针；主文档路径保持不变，AGENTS.md 的入口不迁移。
- `archive/<任务ID>.md`：按任务保存原始事件及关闭证据；同一任务有多个事件节时一次收齐，不向已关闭档案追加后续批次；复开任务用新批次ID并引用旧档案。
- 旧 `archive/<同名主文档>` 保留可检索，不强行拆分或搬迁；没有当前态块的旧文档只能在授权后人工迁移/归档。

## 归档判据

**完成不等于可归档**。模型核验 done、verified=true、openItems为空及非空 evidence/summary；等待验收、仍有待办、约束尚未迁入当前态时不得归档。不能按“完成”等关键词推断。已获该目录交接维护与归档授权后，由模型自行完成检查和归档，不再逐项请求确认；新的权限、无法判断的验收或并行修改仍须停下。

主文档活跃预算（当前态块+§0）>20480 字节时提醒处理，与 index/Stop 口径一致；整文件 48KiB 只是叙事堆积兜底提醒，不作为归档前置条件；这不是精确 token 阈值。先归档已闭环旧节，再写新节；不得为省空间把新请求并入旧节。没有可归档任务时报告原因、建议拆小当前批次，不删除关键约束或未完成工作来压线。用户正在编辑时停止，不为追平文档而抢写。

## 操作流程

1. 在已授权目录核验任务证据、验收与未决项；仍适用的约束/裁决留在当前态，来源保留原文引用。事件开头标 `**task**: <ID>`，稳定节号不重用。
2. 更新当前态并运行 `refresh`。模型已确认范围、闭环及章节归属时，可直接运行 `archive "<目录>" <ID> --apply`；不确定搬哪些节时才先不带 `--apply` 预览，默认预览不写文件。不是每次归档都让用户手动操作。
3. 脚本以协作锁和字节复核检查并发，先备份原文/STATE、写档案并校验，再从活跃区移出整节、留下归档指针、刷新派生视图。两个功能分别传各自子目录，备份、归档和锁不能共用。
4. 运行 `validate` 与一次限额 `search "<目录>" "锚点" --task <ID>` 核查来源；只有维护既有索引或确需目录时才运行 `index`。归档后的原始事件字节（含CRLF）须保持一致，主文档与派生区不要求保持旧格式。
5. 报告备份位置。中断后先核对磁盘与备份，不盲目覆盖恢复；已完成同一归档再次调用不重复写入。目标不同或锁已存在即停止，不删他人的锁。

脚本不会移动主文档、修改AGENTS.md/.gitignore、删除旧档案或提交git。若有外部引用直接指向已迁出章节，必须先协调修复引用；AGENTS.md 编辑仍需单独授权。所有原文搬移都以授权为前提，不因hook提醒自动执行。

## 瘦身/归档落盘的工具体质（跨项目通用，勿在项目交接文档里各存一份）

- **Windows 下 `io.open(p,'w'|'a')` 默认把 `\n` 转成 `\r\n`，每行虚增 1 B** → 明明零改动也可能从阈值下涨到超限（实测 20391→20484 破 20 KB）。读写一律带 `newline=''`，写完立刻 `wc -c` 复核
- **here-doc（`<<'EOF'`）落盘多行文件不可靠**（被截断、误报 UNC 路径）→ 脚本与整节内容用文件写入工具落盘，再由脚本读取拼装
- **控制台中文常显示成 GBK 乱码**，不代表文件内容坏了 → 核对文档内容改用 `python -c` 打印 `unicode_escape`，或只看 ASCII 数字（字节数、行号）
- **`re.search` 未开 MULTILINE 时 `^` 只匹配串首** → 按 `^## N、` 定位小节必须显式 `re.M`，否则会误判"该节不存在"
- 归档前先备份：活跃区与档案**两个文件都要备份**（追加式写入同样不可回退），命名 `.backup/<文件名>.pre-<用途>-<日期>.md`
- **`grep -c` 统计的是"含匹配的行数"，不是出现次数** → 文档里写"共 N 处"必须用 `grep -o X file | wc -l`（实测同一文件行数 33 / 出现次数 48）。凭 `grep -c` 写出的计数是**编造数字**，核对时会被自己反咬一口
- **体积必须在最后一次内容新增之后再测**：先压缩到达标、再补验证证据/新条目 → 又破线，本轮 23052→20280 为此往返 6 轮。正确顺序＝**先把本轮所有要写的字写完，再算体积、再做压缩**
- **同一条坑的多次发生要合并成一条**（如"文档基线落后 HEAD"在 09-09 与 09-14 各记一次）：合并后按"现象—各次实例—根因—强制动作"一行承载，；保留原始依据并核查关键事实，比逐条改措辞省得多（实测单条 -200 B）。逐条润色是低效瘦身，合并同类才是
- **`grep -c $'\r'` 不能当行尾判据**：同一份纯 LF 文件，先后返回 `0` 和「总行数 86」两种结果（ANSI-C 引用在命令包装层里的展开不稳定）→ 核行尾一律用二进制字节计数：`python -c "b=open(p,'rb').read(); print(len(b), b.count(b'\r\n'), b.count(b'\n'))"`
- **别把实测体积写进文档正文**：一旦写了，之后任何一次编辑（包括为压体积而做的编辑）都让这个数变成过期事实，还得回填 → 只能"最后一次改动之后再填"，且填完不再动。要么只记阈值不记实测值，要么填完立刻用同一命令复核 `len(b)` 与文中数字一致
- **压体积时禁止改动"定位用字面"**：活跃区里用于去归档 grep 的条目标题／节名指针（如「补偿同步范围（已失效）」「瘦身移出条目（第八次）」）属**寻址键**，缩一个字就查不到，等于把归档内容弄丢。实测本轮把归档标题缩字后指针即失效，只能回滚。**正确替代**：指针不必逐字抄标题，改成"搜「<一个短且唯一的锚点短语>」"，并在写入前用该短语真跑一次 `grep -n` 验证命中；同样地，删章名枚举可以，但前提是**目标文档自带目录**且留了"索引看 X"的指向

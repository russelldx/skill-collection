# 跨窗口共享文件协调

> 触发：多个独立会话窗口并行修改同一项目，且可能触碰同一文件时 Read 本文件。单窗口或文件域不相交时不启用、不创建协调记录。
> 创建/更新 COORD.json、冲突档案须先获用户持久化授权；本文件不扩大 git、AGENTS.md、全局配置权限。协调是参与者共同遵守的协议，不是操作系统级文件保护。

## 1. 结构

```text
.handoff/
├── login/          功能交接（不变）
├── export/         功能交接（不变）
└── _coord/
    ├── COORD.json  文件占用 + 冲突状态（脚本维护）
    └── conflicts/
        └── C001.md 本次共享修改的需求/决定/改动/证据（agent 填写）
```

- COORD.json 只记占用与状态，不复制各功能目标、进度、历史。
- 冲突档案由协调窗口在子 agent 返回后填写；两个功能的交接只引用它，不重复抄写。
- 多 worktree 并行时，所有窗口指向**同一份** COORD.json 的绝对路径，不各自建副本。

## 2. 命令

```bash
# H 换成你本机 session-handoff 的实际安装路径
H="<session-handoff 安装目录>/scripts/handoff.py"
C=".handoff/_coord"

# 认领本批文件（整批成功或整批拒绝）
python "$H" claim "$C" --session <会话ID> --feature <功能目录> --files src/a.ts,src/b.ts

# 查询与本会话/本批文件相关的记录（有界输出）
python "$H" coord "$C" --session <会话ID>
python "$H" coord "$C" --files src/common.ts

# 确认已停止写入并移交；首个 --coordinator 指定协调者
python "$H" handoff "$C" --conflict C001 --session <会话ID> --coordinator

# 记录本会话验收；全部参与方通过后自动关闭并释放认领
python "$H" verify "$C" --conflict C001 --session <会话ID>

# 正常完工释放（无冲突时）
python "$H" release "$C" --session <会话ID>
```

## 3. 冲突流程

1. **认领**：`claim` 原子登记。与另一活跃会话文件重叠 → 创建冲突（state=open），返回冲突编号与重叠文件。不重叠 → 正常登记。
2. **暂停共享部分**：相关窗口停止修改重叠文件，不相交部分继续。新窗口不能再认领协调中的文件。
3. **移交确认**：每个参与方运行 `handoff`，表示已停止写入、当前改动已保留。**未回复不等于已暂停；超时不自动夺取修改权。** 全部确认后 state=ready。
4. **单一执行者**：协调窗口（`--coordinator` 指定，每个冲突仅一个）派一个子 agent，只改已移交文件，同时满足各方需求与验收。子 agent 不改交接、不提交、不切分支。发现需改其他文件 → 先重新协调范围。
5. **记录与验收**：子 agent 返回后，协调窗口核对实际差异与证据，填写冲突档案，state 仍为 ready（待验收）。各参与方读取结果、重新读相关代码、验证各自功能后运行 `verify`。
6. **关闭**：全部参与方 verify 后 state=closed，认领自动释放。各功能更新自己的交接并引用冲突档案。

“共享文件改完”与“两个功能都验证通过”是两个状态，不能混为一谈。

## 4. 冲突档案内容（agent 填写）

| 内容 | 用途 |
|---|---|
| 冲突编号、相关功能、协调窗口 | 谁参与、谁负责 |
| 共享文件及移交时版本依据（哈希/差异） | 避免据旧代码修改 |
| 各方需求与不可破坏条件 | 防止只满足一方 |
| 最终取舍及理由 | 为什么这样改 |
| 实际修改范围与差异位置 | 找到真正改动 |
| 验证命令、结果、证据路径 | 区分声明与验证 |
| 未决问题、各方验收状态 | 正确接续 |

无 git 提交时用文件哈希与保留差异作版本依据，不为留记录而擅自提交。关闭后可归档但保留稳定引用；仍有功能待验收时不提前归档。

## 5. 交用户裁决的情形

子 agent 可处理兼容的实现调整，但以下不得自行拍板：

- **需求互斥**：同一接口被要求采取相反行为。
- **需改变既定约束**：修改公共接口、数据模型或引入不兼容变化。
- **已有改动无法安全区分**：共享文件被交错修改，无法确认保留哪些。
- **存在未确认修改者**：窗口失联、用户正在编辑、磁盘出现来源不明变化。
- **需额外权限**：扩大文件范围、安装依赖、改配置、未授权 git 操作。
- **验证不能证明兼容**：无法确定修复同时满足双方。

提问时给出：冲突事实、可选方案、各自影响、推荐项。用户裁决后协调者先记录决定再恢复执行。

## 6. 边界

- 协调记录写入用短锁（更新 COORD.json 时持有）；文件占用持续到释放或移交。开始改新发现的共享文件前必须先扩展认领。
- 不安装常驻服务、不持续轮询、不默认启用全局 hooks。
- 不创建永久“冲突专家”配置；需要时派发现有类型子 agent。
- 协议不能强制阻止未接入的窗口或编辑器写入；发现此类变化即停止，不宣称绝对无冲突。
- 不删除他人占用记录来“解锁”；失联窗口保持阻塞，交用户决定接管。
